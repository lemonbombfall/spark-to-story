# 碎片整合

把已有正文提取成场景卡，让作者在便签墙上亲手发现结构。AI 负责提取和展示，作者决定顺序与连接。

## 1. 征得 permission，读取原文

读取前确认用户允许处理哪些文件；用户已明确授权读取指定文件时直接继续，不重复询问。支持 `.docx / .md / .txt`，长稿按场景分段读取。

正文始终以原文件为准。卡片摘要和拖拽操作不修改原文；读取失败或内容不完整时说明具体缺口，不凭空补全。

## 2. 自动提取 Scene Card，保存结构状态

依据现有章节、场景分隔提取卡片；边界不明确时标记供作者确认。每张卡保留稳定 ID 和来源位置，包含：

- 章节／场景编号。
- 视角人物。
- 发生了什么。
- 停在什么位置。
- 需要记住的细节。
- 可选：时间、地点。

内容简短，以原文为据；未知信息留空或标为未明。来源位置使用文件路径及章节、段落或行号，便于返回原文。

结构状态保存卡片摘要、来源、桌面坐标、用户排出的顺序及 GAP 标记。正文不进入 memory，也不复制进结构状态或 HTML；需要正文时重新读取原文件。这里的 memory 仅用于结构摘要，不自动调用跨项目的长期记忆服务。

原文更新后，只更新受影响的卡片；保留用户已有排列，场景拆分或合并导致对应不明时请作者确认。

## 3. 生成单文件 HTML 便签墙

使用固定模板 [scene-board.html](../assets/scene-board.html)，只填数据，不现场重写界面：

```bash
python3 <skill目录>/scripts/build_board.py --state <场景状态.json> --output <便签墙.html>
```

状态为 `version: 1, project, cards, timeline, selected, note`。每张卡包含 `id, kind: scene, title, file, source, number, pov, event, stop, details`；可含 `time, place, x, y, sourceHash`。`file` 相对状态文件目录，`source` 定位原文；正文不放入状态。首次 `timeline: []`，`selected: null`，`note: ""`；更新时沿用已有 ID、排列和 GAP。

模板提供散乱桌面、手动 Timeline、GAP、滚动和卡片选择入口；重叠时可点卡名提到最上面。单文件离线运行，AI不自动排序或补洞。缓存／导入只恢复布局，摘要使用当前数据。

“排好了，继续写”展示可复制的回传内容，也可下载 JSON。说明用户需交回对话，不把按钮成功当作 AI 已收到。浏览器不能存储时，用下载或复制备份。

## 4. 接回编排结果，继续陪写

收到用户回传的状态后，读取实际排列、GAP、选中位置和备注，将其作为本轮结构依据，不重新替用户排序。明确的文字排列也可作为回传；未提供坐标时不猜测。尚未收到结果时请用户回传。

用户已选中场景或 GAP，就从那里开始；未选择时，结合实际编排提出一个具体问题，例如：“你把车站放在重逢前面，中间留了 GAP。想先回读车站的结尾，还是先写重逢时浮现的画面？”不逐个审问所有空缺，也不默认从第一个 GAP 开始。

按需回读相关原文，用人物眼前的感知或行动帮助重新进入自由写作。GAP 可以继续留着，Timeline 也可以再改；编排结果不变成必须遵守的大纲。

用户写出新内容并保存到原文后，更新受影响的 Scene Card 和结构状态，保留原有 ID、排列及未解决的 GAP，再供用户查看或拖动。新场景放在哪里、某个 GAP 是否已接上，由用户决定，不自动删掉 GAP。

循环为：**原文 → 场景卡 → 用户编排 → 回传结果 → 按当前位置陪写 → 更新卡片 → 再编排。**

## 交付与暂停

交付 HTML 便签墙，并简短说明拖动、插入 GAP 和“排好了，继续写”的回传方式。验证卡片与来源对应，拖入／调序／拖回、GAP 操作、状态导出／恢复及选中位置回传可用，且原文未被改动。无法运行浏览器验证时，明确标注未验证的交互。

交付便签墙后暂停等待用户编排；收到结果后接回陪写，不把 HTML 交付视为整个流程结束。用户想休息时暂停，不为消除未知而持续补写。

## 来源与设计补充

原书依据：第七章的乱序创作、第九章的写后大纲，以及第八章的回看与细节核对。

用户指定的交互设计：读取许可、Scene Card、只保存结构状态、正文不进 memory、单文件 HTML 散乱桌面、手动 Timeline、不自动填补的 GAP，以及编排后返回陪写并更新卡片的闭环。状态导出／恢复和回传入口用于支持该交互，不是原书方法。
